# 墨隐 · 本地文档脱敏

独立编写的离线桌面文档脱敏应用。2.15.0 补齐识别与逆脱敏核对两大短板：新增“密码/密钥”识别类型、空格撑开的姓名与后文重复补全、导出前残留检查，以及逐句的逆脱敏语义核对单；同时把识别、代号化与逆脱敏改为线性复杂度，百万字文档识别从约 130 秒降到 1 秒以内。

## 2.15.2 新增：表格台账按列识别

- **按表头识别表格列**：Excel/CSV 台账（如全量发票查询导出）里，姓名、单位名称只出现在格子里、没有“联系人：”前缀，原规则一个都认不出。现在先识别表头，再把整列按类型识别：
  - 人名列：姓名、开票人、收款人、复核人、经办人、报销人、旅客姓名、司机、员工等；一格多个名字（顿号、斜杠分隔）和“工号(姓名)”写法也能拆出；首字不是常见姓氏的标为需核对；“系统”“微信”“合计”等不当作人名。
  - 单位列：销方名称、购买方名称、供应商、客户、收款单位等，不带“公司”后缀的个体户、加油站、餐馆也能认出；计量“单位”列不会误判。
  - 地址列、银行卡号列同理。识别结果标注“表格列：列名”。
- 行内人名标签补充开票人、收款人、复核人、审批人、报销人、领款人、制单人、出纳、司机等财务单据常见写法。
- 减少数字误报：小数（单价）中的长数字不再当成手机号；银行卡号要求 3–6 开头或前文有卡号/账户字样，排除末尾补零的编码（如 19 位税收分类编码）；不带区号的固定电话需要前文有“电话/传真”等字样，排除重复数字串。
- 实测一份 690 行的全量发票导出表：姓名识别从 0 提升到 249 人、1,923 处；开票人/旅客姓名列覆盖 1222/1224 格（剩下 2 格不是人名），备注中的收款人/复核人真实姓名全部覆盖；误报的电话、手机号、银行卡号从约 100 处降到 0；导出的 XLSX 中无人名残留。

## 2.15.1 新增：原文手动补选与高亮

- **在原文里直接补选漏项**：在“原始内容”中用鼠标选中任意文字，上方出现补选工具栏，可选择“只隐藏这一处”（快捷键 Ctrl+Enter）、“全文同样的都隐藏”（自动写入左侧类型化隐藏词，以后重新识别也生效）或“这个词不隐藏”（写入总是保留词）。类型按内容自动猜测（公司后缀、常见姓氏、地址用字、已有规则），可手动改。
- 手动补选优先于自动识别：选中范围与自动结果重叠时以手动为准（例如把识别短了的公司名补全）；该类自动识别关闭或词在“总是保留”里时，手动补选仍生效。补选项在识别结果中以蓝色标出“手动补选”，可一键“移除”。
- **原文高亮**：已隐藏的位置标黄、手动补选标蓝、需核对标橙、已取消勾选划灰线，漏掉的地方一眼可见；点击识别结果中的原文可跳转定位。超过 60 万字的文档不做高亮以保证流畅。
- 补选只标记选区、不改动原文，因此 Word/Excel/PDF/CSV 原格式导出不受影响。

## 2.15.0 新增

- **密码/密钥识别（独立类型，可单独开关）**：中英文关键词后的取值（密码、口令、PIN、验证码、密钥、password、api_key、access_token、AccessKey Secret、`--password=` 等）；`Authorization: Bearer/Basic`；表格导出时键与值分在相邻两格（制表符）；连接串里的密码（`mysql://用户:密码@主机`）；PEM 私钥块（RSA/EC/DSA/OPENSSH/ENCRYPTED/PGP）、SSH2 与 PuTTY `.ppk` 私钥正文（首尾标记行保留）；无关键词的知名凭据格式（AWS、GitHub、`sk-` API Key、Slack、Google API Key、JWT、阿里云 AccessKey ID）。说明文字、占位符（`******`、`${VAR}`、`<...>`）、代码变量（`request.form.get`、`process.env`）、版本号、文件名和“Token：128000”这类用量数字不认。强密码（6 位以上字母数字混合或 10 位以上）在后文单独再出现时自动补上。
- **空格撑开的姓名**：负责人、联系人、经办人、签字人、法定代表人、授权代表、审核人、收款人等栏目后，字间夹普通空格、全角空格或不换行空格的姓名都能识别，并合并为同一人。
- **后文重复补全**：规则认出的姓名、公司、密码在全文其他位置自动补上（姓名允许字间夹空格）。两个字的名字两侧紧挨汉字时不补；三四个字的名字紧挨汉字时补上但标为“需核对”。
- **导出前残留检查（不拦导出）**：通过校验位但未隐藏的 18 位身份证号、银行卡号（62 开头或前文写着卡号/账户，支持 4-4-4-4 分组写法），以及已隐藏值在别处的未隐藏副本；只露前后四位，逐项说明原因（未识别 / 已取消勾选 / 该类已关闭），可“定位”或“隐藏这一处”，人工补选在重新识别后保留。
- **逆脱敏语义核对单**：逐句对齐“发给 AI 的代号副本”与“AI 返回内容”，列出
  - 金额、日期、比例、数量变化（`100万元` 与 `1,000,000元`、中文大写金额视为相同）；
  - 身份代号增减，以及代号集合不变但先后顺序颠倒（如“甲向乙付款”被写成“乙向甲付款”）；
  - 否定/条件词、付款状态（已付/未付/应付/逾期等）、付款方向变化；
  - AI 直接写出的原文（汉字间空格、号码中的空格或横线不影响比对；副本里本来就露着的不算）；
  - 残缺代号（如丢了方括号，给出建议但不自动换回）、未知编号与其他文件的代号；
  - AI 新写的内容、只改措辞的句子、原副本中被省略的句子数。
  存在需核对项时，必须勾选“已逐项核对”才能导出逆脱敏文本；原格式（DOCX/XLSX/PDF/CSV）逆脱敏同样生成核对单。
- **性能**：候选去重、覆盖判断、替换拼接、代号生成与逆脱敏全部改为线性算法；120 万字、7.3 万个候选的压力样本：识别 0.9 秒、残留检查 1.9 秒、逆脱敏核对 13 秒。顺带修复了原代号生成在原文已含同名代号时会死循环的问题。

## 已实现

- Electron 安全基线：sandbox、contextIsolation、无 Node 注入、CSP，以及导航、弹窗和权限拦截；IPC sender guard 允许同一入口文件的 hash/query 路由，但拒绝其他文件和非 `file:` 来源。
- 导入 TXT、Markdown、CSV、JSON、PDF、DOCX、XLSX、PNG、JPG、WEBP、BMP、TIFF；所有模型与解析均离线运行。
- 规则、类型化自定义词和可选本地 ONNX NER 合并识别；覆盖手机号、身份证、邮箱、银行卡、IP、固定电话、姓名、公司、地址、统一社会信用代码、密码/密钥等。
- OCR 支持方向校正、低分辨率增强、低置信度人工校正、表格/合并单元格和双栏阅读顺序；Tesseract 低置信度结果会尝试 ±90° 候选，普通横排页面不增加旋转识别。
- 随包中文 BERT NER 模型采用固定哈希 manifest 自动校验并后台加载；CPython 3.13.15、RapidOCR 3.9.2、ONNX Runtime 1.29.0 与 PP-OCRv6 Small 作为完整离线运行时逐文件校验并自动启用，界面仍可切换到 Tesseract.js。
- OCR 固定语料基准覆盖中文低分辨率、低对比度、合并表格和双栏；RapidOCR 当前 CER/WER 均为 0，Tesseract.js 为 CER 0.010526 / WER 0.037037。
- PDF 支持最多 100 MiB、300 页的流式工作区；原生文字页与扫描页统一映射坐标，并正确处理 0/90/180/270 度页面。
- PDF 不可恢复涂黑会替换旧内容流和旧 XObject；保留旋转、MediaBox/CropBox、AcroForm、Widget/Link 批注、嵌入字体、XFA 与 PDF/A 声明，并显式报告签章在修改后失效。
- 带密码 PDF 通过受控对话框导入，密码只进入当前任务内存；错误密码可重试，解密后的源文件不会落盘，最终结果走安全栅格重建。
- PDF 导出后自动调用可选 veraPDF CLI JSON 校验适配器；缺少 CLI 时明确报告未安装，不把“声明存在”误报成“规范通过”。
- 重新签名支持 PKCS#12 证书实签和 PKCS#11/HSM 异步回调适配器，使用 PAdES CAdES detached 子过滤器并生成有效 ByteRange/CMS。
- PDF/DOCX/XLSX 支持不可恢复脱敏及可逆令牌往返；DOCX/XLSX 保留 OOXML 其他部件、样式和公式。
- CSV 专用链保留 UTF-8/UTF-16LE/UTF-16BE/GB18030 编码、BOM、逗号/分号/TAB/竖线方言、原换行与引号/跨行字段；导出时阻断公式注入，可逆代号恢复后可与源文件逐字节一致。
- 批处理支持拖放、串行队列、取消、冲突安全命名、去敏审计清单，以及成功导出项可选自动加密入库。
- AES-256-GCM + scrypt 本地仓库使用 v3 分块认证容器和 v4 逻辑索引，支持 v2 原子迁移、备份导入、密码轮换、条目删除、游标分页和原子压缩回收。
- 原件和脱敏副本作为隐藏加密 file-blob 保存；SHA-256 内容寻址让跨记录相同文件只存一份，删除记录只清理失去全部引用的孤儿 blob。
- 单文件导出可显式保存“原件＋脱敏副本”，批处理自动入库也携带成功项的原件与副本；列表显示附件数并可逐项另存，解密导出后再次校验 SHA-256。
- 备份导出/导入活动写入 AES-256-GCM 认证索引，锁定或重启后仍可恢复；仅保存动作、时间、basename、计数和可选 SHA-256，不保存目录路径、密码或 token。
- 活动历史限制为 20 条，随仓库压缩、密码轮换和加密备份保持；导入时合并来源与本地历史并按 ID 去重。
- 仓库已验证 256 MiB 对齐容量和 1 GiB 长跑；2 GiB 写入边界在处理前拒绝。
- 所有解析与脱敏均在本机完成；应用没有联网业务代码。
- 五个一级任务入口分别提供三步清单、状态徽标和唯一主操作；支持 URL hash、方向键/Home/End、Ctrl+1～5，并为批处理提供原生多文件选择器。
- 首屏可直接粘贴文字或选择图片转 TXT；粘贴内容保留换行并显示字符/字节计数，图片链复用 RapidOCR 与人工校正后提供独立识别文本出口。
- 已解锁仓库可按会话开启“导出后自动入库”；默认关闭，只在成功导出后执行，锁定、取消导出和逆脱敏会话不会触发。
- 仓库支持按编号、名称或敏感类型搜索，组合脱敏/可逆类型与起止日期筛选；备份导出和导入结果显示在当前解锁会话历史中。
- 首屏提供与隐页工作流一致的三步引导、格式范围、隐私说明和“用示例试一试”；本地虚构示例一次覆盖公司、姓名、手机号、邮箱、银行卡、地址、IPv4 与自定义词，并把流程推进到人工核对。

## 当前边界

附件单文件上限 100 MiB、每条记录最多 8 个附件；当前读取受限文件后交给 1 MiB 分块加密容器。活动历史只记录备份动作的最小元数据并限制 20 条。Office 长尾报告覆盖透视表/缓存、外链、名称范围、数据验证、条件格式、SmartArt、嵌入对象和关系包，并对不重算/不执行的部件明确标记 `degraded`；报告位于 `output/office/phase31-long-tail-report.json`。Phase 34 报告位于 `output/ocr/phase34/ocr-vertical-report.json`；RapidOCR 与 Tesseract 六场景总召回均为 1.0，竖排恢复会记录方向、识别次数和所选分割模式。报告仍统计 CER/WER、平均/P95 耗时和父进程峰值 RSS。PDF 结构保真路径覆盖 0/90/180/270 度和非默认 CropBox；XFA 保留但不解释业务规则。旧式二进制 `.xls` 仍导出文本；受密码保护的 Office 文件需要先解除保护。
