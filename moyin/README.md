# 墨隐 · 本地文档脱敏

独立编写的离线桌面文档脱敏应用。2.15.0 补齐识别与逆脱敏核对两大短板：新增“密码/密钥”识别类型、空格撑开的姓名与后文重复补全、导出前残留检查，以及逐句的逆脱敏语义核对单；同时把识别、代号化与逆脱敏改为线性复杂度，百万字文档识别从约 130 秒降到 1 秒以内。

## 2.20.1：批处理失败可查，Excel 工作表名与文档属性脱敏

- **批处理导出失败看得到**：队列中导出失败的文件标红并写明原因（中文说明）；导出结束后队列上方常驻结果摘要，列出失败文件与原因（税务筛查模式下换回原文件名），并提示失败明细在“墨隐-批处理清单.json”。此前只显示“N 失败”，无法知道是哪些文件。
- **修复泄露：Excel 工作表名称**此前不会被改写，名称里的公司名、人名会原样留在副本中；只有工作表名里有敏感信息的文件还会导出失败。现在工作表名按代号/假名改名（代号去掉方括号，非法字符换成下划线，不超过 31 字符、不重名），公式、定义名称、图表中的引用一并更新；逆脱敏时改回原名。
- **文档属性清空**：导出的 Excel、Word 副本清空作者、最后修改者、公司、管理者、标题、主题、关键词等属性（常含企业名称）。
- 批次中文档数超过同时保留上限时，Excel/Word/CSV 从原文件重新读取，避免“会话已失效”。
- 错误说明更准确：区分“没有可写回的隐藏项”与 PDF 导出时“找不到能写入代号的文字位置”。
- 回归：税务筛查技能对原件与脱敏件的 107 条规则结果仍逐条一致，还原后的报告与台账内容一致（仅生成时间不同）。

## 2.20.0：仓库批量管理，逆脱敏下拉选择记录

- **仓库管理移到主区域，做成表格**：编号、名称、类型（单文件 / 批次 / 税务筛查 / 脱敏文本）、日期、代号数、操作；搜索、类型、日期筛选在同一行；解锁后不再显示说明卡片，左侧只保留打开/锁定、备份导入、自动锁定、轮换密码、压缩等设置。
- **多选**：逐条勾选、Shift 连续选择、全选本页、“全选筛选结果”（一次选中所有符合条件的记录，不限当前页）。
- **详情面板**：点一行在右侧查看名称、创建时间、各类代号数量、批次包含的文件、附件下载，以及去逆脱敏、删除。
- **批量删除**：墨隐自己的确认框列出要删除的编号，提醒删除后已外发的副本无法换回，可“先导出所选备份”；按 Enter 不会删除，须点击删除按钮。后台一次提交索引。删除后提示“旧的加密内容仍在仓库文件里，建议压缩回收空间”，由用户决定是否立即压缩。
- **导出所选记录的备份**：只包含所选记录及其引用的附件，便于按企业单独备份或迁移。
- **逆脱敏：下拉选择记录**：点开即列出仓库中的可逆记录（最新在前，显示编号、名称、类型、日期），输入编号或名称即时筛选，可加载更多；仓库锁定时点一下即解锁。导入返回文件时按编号自动选中的功能保留。

## 2.19.0：与“建筑业税务风险筛查”技能衔接（税务筛查模式）

- **问题**：筛查技能的规则靠名称、税号、地址本身的特征判断——是不是个人（2–4 个汉字、常见姓氏开头，或证件号是身份证号）、是不是个体户（税号 92 开头或“个体工商户”字样）、机构所在地（税号第 3–8 位区划码）、单位类别（“加油站”“运输”“劳务”等字样）。换成方括号代号后，这些规则全部失效。
- **税务筛查模式（批处理 → 导出方式）**：换掉身份、保留类别特征——人名换成“张甲子”式三字假名；单位只把字号换成 Q 编号（保留地名前缀、行业词、组织形式和“（个体工商户）”字样，无字号的名称只保留通用行业词）；统一社会信用代码保留前 8 位并重算校验位；身份证号保留前 6 位区划码、日期与校验位合法；地址保留到区县；银行账号（Luhn 正确）、电话换成同格式假号。同一对象全批同一假名，假名不与原文重复。
- **干净的资料文件夹**：只导出技能读取的 Excel、CSV（.xls 转为 .xlsx），资料放在“MI-编号-税务筛查资料”，审计记录、清单和筛查专用“给 AI 的要求”放在旁边的“MI-编号-墨隐记录”，不干扰技能的文件读取登记；Word、PDF、图片列为未导出。
- **整个文件夹还原**：把技能生成的“筛查结果”文件夹拖进逆脱敏页（或点“还原整个文件夹”），按路径中的编号自动找到批次记录，报告（.md/.docx）、整改台账（.xlsx）一次换回到“筛查结果-已还原”；.json 跳过。单独出现的单位编号（如“Q007”）换回全称；副本文件名换回原文件名。单个 Markdown 文件逆脱敏后仍存为 .md。
- 仓库与原格式逆脱敏支持假名形式的对照表；单条记录的对照表上限提高到 10 万项。
- **实测**（2025 年发票导出 + 2024 年科目余额表，用技能本身对原件和脱敏件各跑一次）：107 条规则的命中 / 未命中 / 缺数据逐条一致（19 / 41 / 47），16 条线索的等级、金额、年度、事实完全一致；机构所在地区划码不变；还原后的筛查报告 .md（779 行）、.docx、整改台账 .xlsx 与原件运行的结果逐行相同。

## 2.18.0：批处理改为“批次”——整批一个编号、一套代号

- **此前的问题**：批处理按默认的“保留轮廓”导出（`张*`、`潍坊***`），不可逆；仓库里每个文件各存一条“脱敏文本”记录；每个文件代号各自独立；也不使用保护设置。AI 基于整批文件写的报告无法逆脱敏。
- **整批共用一套代号**：两轮识别——先汇总整批认出的公司、人名（人名 3 字以上、公司 4 字以上）作为本批词表，再逐个文件识别；同一对象在所有文件里是同一个代号，AI 可以跨文件、跨年度对比。
- **整批一条仓库记录、一个编号**：对照表合并保存为一条可逆记录（“批次 · N 个文件”），副本按“MI-000123-01-…-脱敏副本.xlsx”命名；导出目录自动生成“MI-000123-给AI的要求.txt”（说明批次编号、跨文件同一代号同一对象，不含原文）。
- **文件名脱敏**：原文件名中的公司名、人名换成本批代号，批处理清单中也不再出现原文件名。单个文件导出的文件名同样处理。
- **逆脱敏**：选这一个批次编号即可换回 AI 的报告或返回的任意文件；批次记录不把其他文件的代号算作“缺失”。
- 批处理沿用保护设置（开启的类型、自定义词、类型化词、保留词）；PDF 在批次模式下写入可逆代号并生成坐标副本。
- 实测“2025 年发票台账 + 2024 年科目余额表”一个批次：1,112 个代号、7,974 处，两份文件共有的 21 个对象（供应商、开票人等）代号一致，引用两份文件代号的报告一次换回，单个文件原格式逆脱敏后与原文逐字一致。

## 2.17.0：左右两栏核对面板（按列 / 逐条），识别设置移入保护设置

- **左右两栏**：导入文档后收起侧栏，左边是带高亮的原文，右边是“要隐藏的信息”面板（滚动时固定在视野内），页底是导出栏。
- **按列视图**（表格文档默认）：按“工作表 → 列”分组，每列一张卡片：列字母与表头、处数与不同值个数、类型、来源（按表头 / 按内容推断 / 往来明细 / 手动补选）和“请确认”标记，“全部隐藏 / 全部保留”，展开后可设处理方式——只隐藏格内识别到的部分（默认）、整列隐藏并指定类型（适合车次、车牌、编号等规则认不出的列）、整列保留——并预览“值 → 代号”。没有识别结果的列也列出，便于整列隐藏。表格以外的内容单独成组。
- **逐条视图**：按类型分组，同一个值合并成一行（如“孙××  51 处”），一个勾选框管全部出现位置；点值或处数在原文中依次定位。值列表分页显示，几千处的表格也不卡。
- **单元格内换行**不再把表格切成多段：续行并回同一格，列结构与 Excel 一致。
- **识别类型开关移入保护设置**：类型开关和自定义词、类型化词、保留词的改动先暂存，显示“有改动未应用”，点“应用并重新识别”才生效；核对面板显示“已开启 N 类 · 保护设置 ↗”。
- 实测 7,009 处的发票导出表：加载并渲染约 1.4 秒，展开一列约 0.3 秒，勾选一个值约 0.5 秒。

## 2.16.3：科目余额表按科目层级识别往来对象，支持旧版 .xls 原格式

- **科目余额表专用识别**：第一列是科目代码时，往来类科目（应收、应付、预付、预收、其他应收/应付、备用金、借款、保证金、职工、实收资本/股东等）下各级明细按往来对象识别：人名（含“××保证金”“××个人借款”“××考核”“××（禁用）”等写法）、单位（含“××局”“××中心”及“单位.项目”写法）、单位简称（标为需核对）；工程项目、地点、材料、车队/拌合站等不识别。实测一份 1,877 行的科目余额表：人名从 0 提升到 278 人，导出副本无人名残留，逆脱敏后与原文逐字一致。
- **旧版 .xls 按原格式处理**：导入时在本机工作目录转为 .xlsx，核对、导出、逆脱敏均保持表格（副本以 .xlsx 导出，单元格样式可能简化）；此前 .xls 只能导出 TXT。
- .xls 中乱码的货币格式（如 "å"#,##0.00）在提取和转换时清理。

## 2.16.2：科目余额表等台账的人名识别

- **按内容推断列**：表头认不出（如“科目名称”“核算项目”）时，统计每列中“像人名”的格子（2–3 个汉字、常见姓氏开头、不是费用/应付/银行等业务词）；至少 3 个且占该列文字格四分之一以上时识别为人名，整列多为人名的直接采纳，混合列中的标为需核对。同一列中不带“公司”后缀的单位（如“××置业”“××饭店”）一并列出并标为需核对。
- 数字格中乱码的货币符号（如“å52,500.00”）在提取时去掉。
- 修复原文高亮在 Windows 上随长行换行逐渐错位的问题：高亮层与文本框使用同宽滚动条，并在运行时校准宽度。

## 2.16.1：串通后半段（AI 返回 → 换回原文）

- **把 AI 返回的文件拖进“逆脱敏”页**（或点“导入 AI 返回的文件”，支持 Word / Excel / CSV / PDF / TXT），墨隐从文件名或开头的“文件 MI-000001”认出编号，自动找到仓库记录并立即核对；也可粘贴 AI 的回复，或按编号、文件名查找记录。
- **先核对、后保存**：返回件只读入内存，核对单出来、勾选确认后，才“下载逆脱敏结果”，并按原格式（XLSX/DOCX/CSV/PDF）换回；手动改过返回内容时自动改为 TXT。
- **就地解锁**：仓库已锁定时，在逆脱敏页直接弹出密码框，不必跳到仓库页。
- 输入框不再预填发出去的副本，避免误把副本当返回内容。
- 核对单中的金额、日期、比例按“950,000 元”“2026年10月30日”等易读格式显示；代号不属于当前文件时给出提示。
- 仓库自动锁定默认改为 30 分钟（可在仓库页修改或随时手动锁定）。

## 2.16.0：主流程串通（导出 → 交给 AI → 逆脱敏）

- **默认可逆代号**：“保留轮廓”“替换标签”移到保护设置的“导出方式（高级）”，并注明不可逆、不入库。
- **一个主按钮“确认并导出副本”**：自动按原格式（Word / Excel / CSV / PDF / 文本）导出；页底常驻导出栏显示“N 处将换成代号 · 导出为 XLSX”，必须先勾选“我已核对要隐藏的信息”。审计 JSON 等收进“更多导出方式”。
- **导出自动入库并编号**：没有打开仓库时，引导“新建仓库 / 打开已有仓库”；代号对照表先加密存入仓库得到编号，再以“MI-000001-原名-脱敏副本”命名导出。取消“另存为”或导出失败时自动撤销这条记录，不留空编号。
- **“接下来”卡片**：导出后显示编号与保存路径，生成“给 AI 的要求”（只含编号、代号格式和各类代号数量，不含任何原文），可复制或下载 TXT；一键“去逆脱敏 →”或“处理下一份文件”。
- **仓库记录直接“去逆脱敏 →”**；删除记录前说明删除后已外发的副本将无法换回，并建议先备份。
- **未导出内容保护**：清空、导入新文档、粘贴新文字、载入示例前，如当前文档还没导出，先确认。
- **错误提示中文化**：内部错误代码统一翻译成中文说明和处理建议；未收录的代码给出通用说明并保留代码便于反馈。
- 顶部统计改为“找到 / 将隐藏”。

## 2.15.2 新增：表格台账按列识别

- **按表头识别表格列**：Excel/CSV 台账（如全量发票查询导出）里，姓名、单位名称只出现在格子里、没有“联系人：”前缀，原规则一个都认不出。现在先识别表头，再把整列按类型识别：
  - 人名列：姓名、开票人、收款人、复核人、经办人、报销人、旅客姓名、司机、员工等；一格多个名字（顿号、斜杠分隔）和“工号(姓名)”写法也能拆出；首字不是常见姓氏的标为需核对；“系统”“微信”“合计”等不当作人名。
  - 单位列：销方名称、购买方名称、供应商、客户、收款单位等，不带“公司”后缀的个体户、加油站、餐馆也能认出；计量“单位”列不会误判。
  - 地址列、银行卡号列同理。识别结果标注“表格列：列名”。
- 行内人名标签补充开票人、收款人、复核人、审批人、报销人、领款人、制单人、出纳、司机等财务单据常见写法。
- 减少数字误报：小数（单价）中的长数字不再当成手机号；银行卡号要求 3–6 开头或前文有卡号/账户字样，排除末尾补零的编码（如 19 位税收分类编码）；不带区号的固定电话需要前文有“电话/传真”等字样，排除重复数字串。
- 实测一份 690 行的全量发票导出表：姓名识别从 0 提升到 249 人、1,923 处；开票人/旅客姓名列覆盖 1222/1224 格（剩下 2 格不是人名），备注中的收款人/复核人真实姓名全部覆盖；误报的电话、手机号、银行卡号从约 100 处降到 0；导出的 XLSX 中无人名残留。

## 2.15.1 新增：原文手动补选与高亮

- **在原文里直接补选漏项**：在“原始内容”中用鼠标选中任意文字，上方出现补选工具栏，可选择“只隐藏这一处”（快捷键 Ctrl+Enter）、“全文同样的都隐藏”（自动写入左侧类型化隐藏词，以后重新识别也生效）或“这个词不隐藏”（写入总是保留词）。类型按内容自动猜测（公司后缀、常见姓氏、地址用字、已有规则），可手动改。
- 手动补选优先于自动识别：选中范围与自动结果重叠时以手动为准（例如把识别短了的公司名补全）；该类自动识别关闭或词在“总是保留”里时，手动补选仍生效。补选项在识别结果中以蓝色标出“手动补选”，可一键“移除”。
- **原文高亮**：已隐藏的位置标黄、手动补选标蓝、需核对标橙、已取消勾选划灰线，漏掉的地方一眼可见；点击识别结果中的原文可跳转定位。超过 60 万字的文档不做高亮以保证流畅。
- 补选只标记选区、不改动原文，因此 Word/Excel/PDF/CSV 原格式导出不受影响。

## 2.15.0 新增

- **密码/密钥识别（独立类型，可单独开关）**：中英文关键词后的取值（密码、口令、PIN、验证码、密钥、password、api_key、access_token、AccessKey Secret、`--password=` 等）；`Authorization: Bearer/Basic`；表格导出时键与值分在相邻两格（制表符）；连接串里的密码（`mysql://用户:密码@主机`）；PEM 私钥块（RSA/EC/DSA/OPENSSH/ENCRYPTED/PGP）、SSH2 与 PuTTY `.ppk` 私钥正文（首尾标记行保留）；无关键词的知名凭据格式（AWS、GitHub、`sk-` API Key、Slack、Google API Key、JWT、阿里云 AccessKey ID）。说明文字、占位符（`******`、`${VAR}`、`<...>`）、代码变量（`request.form.get`、`process.env`）、版本号、文件名和“Token：128000”这类用量数字不认。强密码（6 位以上字母数字混合或 10 位以上）在后文单独再出现时自动补上。
- **空格撑开的姓名**：负责人、联系人、经办人、签字人、法定代表人、授权代表、审核人、收款人等栏目后，字间夹普通空格、全角空格或不换行空格的姓名都能识别，并合并为同一人。
- **后文重复补全**：规则认出的姓名、公司、密码在全文其他位置自动补上（姓名允许字间夹空格）。两个字的名字两侧紧挨汉字时不补；三四个字的名字紧挨汉字时补上但标为“需核对”。
- **导出前残留检查（不拦导出）**：通过校验位但未隐藏的 18 位身份证号、银行卡号（62 开头或前文写着卡号/账户，支持 4-4-4-4 分组写法），以及已隐藏值在别处的未隐藏副本；只露前后四位，逐项说明原因（未识别 / 已取消勾选 / 该类已关闭），可“定位”或“隐藏这一处”，人工补选在重新识别后保留。
- **逆脱敏语义核对单**：逐句对齐“发给 AI 的代号副本”与“AI 返回内容”，列出
  - 金额、日期、比例、数量变化（`100万元` 与 `1,000,000元`、中文大写金额视为相同）；
  - 身份代号增减，以及代号集合不变但先后顺序颠倒（如“甲向乙付款”被写成“乙向甲付款”）；
  - 否定/条件词、付款状态（已付/未付/应付/逾期等）、付款方向变化；
  - AI 直接写出的原文（汉字间空格、号码中的空格或横线不影响比对；副本里本来就露着的不算）；
  - 残缺代号（如丢了方括号，给出建议但不自动换回）、未知编号与其他文件的代号；
  - AI 新写的内容、只改措辞的句子、原副本中被省略的句子数。
  存在需核对项时，必须勾选“已逐项核对”才能导出逆脱敏文本；原格式（DOCX/XLSX/PDF/CSV）逆脱敏同样生成核对单。
- **性能**：候选去重、覆盖判断、替换拼接、代号生成与逆脱敏全部改为线性算法；120 万字、7.3 万个候选的压力样本：识别 0.9 秒、残留检查 1.9 秒、逆脱敏核对 13 秒。顺带修复了原代号生成在原文已含同名代号时会死循环的问题。

## 已实现

- Electron 安全基线：sandbox、contextIsolation、无 Node 注入、CSP，以及导航、弹窗和权限拦截；IPC sender guard 允许同一入口文件的 hash/query 路由，但拒绝其他文件和非 `file:` 来源。
- 导入 TXT、Markdown、CSV、JSON、PDF、DOCX、XLSX、PNG、JPG、WEBP、BMP、TIFF；所有模型与解析均离线运行。
- 规则、类型化自定义词和可选本地 ONNX NER 合并识别；覆盖手机号、身份证、邮箱、银行卡、IP、固定电话、姓名、公司、地址、统一社会信用代码、密码/密钥等。
- OCR 支持方向校正、低分辨率增强、低置信度人工校正、表格/合并单元格和双栏阅读顺序；Tesseract 低置信度结果会尝试 ±90° 候选，普通横排页面不增加旋转识别。
- 随包中文 BERT NER 模型采用固定哈希 manifest 自动校验并后台加载；CPython 3.13.15、RapidOCR 3.9.2、ONNX Runtime 1.29.0 与 PP-OCRv6 Small 作为完整离线运行时逐文件校验并自动启用，界面仍可切换到 Tesseract.js。
- OCR 固定语料基准覆盖中文低分辨率、低对比度、合并表格和双栏；RapidOCR 当前 CER/WER 均为 0，Tesseract.js 为 CER 0.010526 / WER 0.037037。
- PDF 支持最多 100 MiB、300 页的流式工作区；原生文字页与扫描页统一映射坐标，并正确处理 0/90/180/270 度页面。
- PDF 不可恢复涂黑会替换旧内容流和旧 XObject；保留旋转、MediaBox/CropBox、AcroForm、Widget/Link 批注、嵌入字体、XFA 与 PDF/A 声明，并显式报告签章在修改后失效。
- 带密码 PDF 通过受控对话框导入，密码只进入当前任务内存；错误密码可重试，解密后的源文件不会落盘，最终结果走安全栅格重建。
- PDF 导出后自动调用可选 veraPDF CLI JSON 校验适配器；缺少 CLI 时明确报告未安装，不把“声明存在”误报成“规范通过”。
- 重新签名支持 PKCS#12 证书实签和 PKCS#11/HSM 异步回调适配器，使用 PAdES CAdES detached 子过滤器并生成有效 ByteRange/CMS。
- PDF/DOCX/XLSX 支持不可恢复脱敏及可逆令牌往返；DOCX/XLSX 保留 OOXML 其他部件、样式和公式。
- CSV 专用链保留 UTF-8/UTF-16LE/UTF-16BE/GB18030 编码、BOM、逗号/分号/TAB/竖线方言、原换行与引号/跨行字段；导出时阻断公式注入，可逆代号恢复后可与源文件逐字节一致。
- 批处理支持拖放、串行队列、取消、冲突安全命名、去敏审计清单，以及成功导出项可选自动加密入库。
- AES-256-GCM + scrypt 本地仓库使用 v3 分块认证容器和 v4 逻辑索引，支持 v2 原子迁移、备份导入、密码轮换、条目删除、游标分页和原子压缩回收。
- 原件和脱敏副本作为隐藏加密 file-blob 保存；SHA-256 内容寻址让跨记录相同文件只存一份，删除记录只清理失去全部引用的孤儿 blob。
- 单文件导出可显式保存“原件＋脱敏副本”，批处理自动入库也携带成功项的原件与副本；列表显示附件数并可逐项另存，解密导出后再次校验 SHA-256。
- 备份导出/导入活动写入 AES-256-GCM 认证索引，锁定或重启后仍可恢复；仅保存动作、时间、basename、计数和可选 SHA-256，不保存目录路径、密码或 token。
- 活动历史限制为 20 条，随仓库压缩、密码轮换和加密备份保持；导入时合并来源与本地历史并按 ID 去重。
- 仓库已验证 256 MiB 对齐容量和 1 GiB 长跑；2 GiB 写入边界在处理前拒绝。
- 所有解析与脱敏均在本机完成；应用没有联网业务代码。
- 五个一级任务入口分别提供三步清单、状态徽标和唯一主操作；支持 URL hash、方向键/Home/End、Ctrl+1～5，并为批处理提供原生多文件选择器。
- 首屏可直接粘贴文字或选择图片转 TXT；粘贴内容保留换行并显示字符/字节计数，图片链复用 RapidOCR 与人工校正后提供独立识别文本出口。
- 已解锁仓库可按会话开启“导出后自动入库”；默认关闭，只在成功导出后执行，锁定、取消导出和逆脱敏会话不会触发。
- 仓库支持按编号、名称或敏感类型搜索，组合脱敏/可逆类型与起止日期筛选；备份导出和导入结果显示在当前解锁会话历史中。
- 首屏提供与隐页工作流一致的三步引导、格式范围、隐私说明和“用示例试一试”；本地虚构示例一次覆盖公司、姓名、手机号、邮箱、银行卡、地址、IPv4 与自定义词，并把流程推进到人工核对。
